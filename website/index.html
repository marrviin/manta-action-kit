How it works

Record a real API flow once in your browser, then let your agent replay it or call those endpoints ad hoc — credentials never leave the browser.

⏺
Step 1 · Record

Capture the flow

Click Start in the popup, use the site normally, click Stop. The extension captures every fetch/XHR — requests and responses, including SSE streams — into a local, inspectable call chain.

⚗️
Step 2 · Distill

Turn it into an Action

Your agent reads the recording through MCP and distills it into a reusable Action — it keeps the parts that change (an order id, a date) as fillable parameters, so one recording runs for every case.

▶
Step 3 · Execute

Run it on demand

Your agent runs the flow through a sandbox gateway. You get a confirmation window before anything is sent; your browser injects the session cookies at send time — the AI never handles them.

Why not just use browser automation?

Manta keeps the agent at the API boundary — it sees the contract, never the session.

Browser-automation agents

Browser-use–style tools put the whole page into the model's context — slow, token-hungry, and your logged-in session sits right there in the transcript.

DevTools-based MCPs

They hand the AI your debugger — page scripts, network traffic, and session all exposed to whatever the model decides to run.

Manta Action Kit

The agent works from a recorded API contract. Replays go through a sandbox gateway with cookies injected at the network layer — your session never enters the model's context.

Why it's safe

Cookie values live in your browser and never travel to the AI — enforced at several layers, not by promises.

🔒 Cookie stays in the browser

Cookies are read via chrome.cookies and injected as a network-layer header. Injected values never appear in tool results, transcripts, or the audit log.

✋ Human-in-the-loop gate

Every new target host pops a confirmation window showing method/URL/body. Recorded actions confirm once per host per run; direct calls confirm per request by default. Deny or ignore and the call never goes out.

🛡 SSRF guard

Loopback, private-network, link-local and cloud-metadata addresses (169.254.169.254 included) are refused before any other policy, on every path.

🌐 Domain policy you own

Deny-list blocks outright, allow-list flows silently. The agent has no tools to read or change these.

🔌 Per-tool kill switch

Toggle any MCP tool off from the extension UI at any time.

📜 Local audit log

Every forwarded call is logged locally. Cookie names are logged; values never.

🤝 Mutually-authenticated bridge

The loopback WebSocket does two-way challenge-response — the token itself never crosses the wire. Unauthenticated peers get dropped.

💾 All data stays local

IndexedDB + chrome.storage. No analytics, no external servers, no remote code.

Scope note: this guarantee covers cookie injection — injected cookie values never reach the AI. Recordings themselves store full request/response data, so if a site uses non-cookie credentials (e.g. an Authorization header), clean them with recording filter rules before sharing the recording with your agent.

Fair questions, straight answers

“Read and change your data on all websites” — that sounds scary.

It's what recording fetch/XHR and injecting cookies on any site you use requires. There's no server on the other end: all data lives in your browser's local storage. And it's MIT-licensed — build it from source instead of installing the store package.

How can I verify cookie values stay private?

Injection happens at the network layer inside the extension — the agent only ever sends method/URL/body. The local audit log records cookie names, never values, and is exportable. Every forward shows you a confirmation window first.

What happens to my data if I uninstall?

Everything is stored in the extension's local storage — uninstalling the extension removes all of it. Recordings, captures and the audit log can also be deleted individually from the side panel.

Quick start

1

Install the extension

Get it from the Chrome Web Store. Requires Chrome 116+ (no Firefox support).

2

Copy the install prompt

Open the extension's side panel → Action tab → Copy install prompt. It embeds your personal bridge token (MANTA_TOKEN).

3

Add the MCP server to your agent

Paste the prompt into Claude Code / Codex / Cursor and follow its instructions — that's the whole setup. Prefer editing config by hand? Add the block below (requires Node.js ≥ 18): 

{
  "mcpServers": {
    "manta-action-kit": {
      "command": "npx",
      "args": ["-y", "@manta-action-kit/mcp"],
      "env": {
        "MANTA_WS_PORT": "8787",
        "MANTA_PROXY_PORT": "8788",
        "MANTA_TOKEN": "<token from the extension>"
      }
    }
  }
}

MANTA_TOKEN is required — copy it from the install prompt; without it the server rejects every client.

4

Use it

Record a flow on your site, then ask your agent: “I just recorded the order-tracking flow. Turn it into an action and tell me where order A1002 is.”
