Introduction

Manta Action Kit lets AI agents (Claude Code, Codex, Cursor, any MCP client) call your real, logged-in APIs — the ones behind your browser session — without ever seeing your credentials.

The suite has two parts: the Chrome extension, which records API calls, captures pages, stores everything locally, and injects your cookies at the network layer; and the MCP server (@manta-action-kit/mcp), which bridges your agent to the extension over a local WebSocket and exposes the tools your agent calls.

The MCP server is only a bridge — it holds no data of its own. Install the extension first; it dials in automatically once the server is running.

Quick start

  1. Install the extension from the Chrome Web Store.
  2. Copy the install prompt — extension side panel → Action tab → Copy install prompt. It embeds your personal bridge token (MANTA_TOKEN).
  3. Add the MCP server to your agent — paste the prompt, or use the config below.
  4. Record a flow on your site, then ask your agent to turn it into an action and run it.
{
  "mcpServers": {
    "manta-action-kit": {
      "command": "npx",
      "args": ["-y", "@manta-action-kit/mcp"],
      "env": {
        "MANTA_WS_PORT": "8787",
        "MANTA_PROXY_PORT": "8788",
        "MANTA_TOKEN": "<token from the extension>"
      }
    }
  }
}

Architecture

An MV3 extension can't listen on a port, so the socket direction is inverted: the MCP server hosts the WebSocket bridge bound to loopback, and the extension dials in as an always-on client. 

agent ──stdio (MCP)──▶ @manta-action-kit/mcp ──WS ws://127.0.0.1:8787──▶ extension (WS client)
                              ◀──── rpc-result {id} ────────────  reads IndexedDB
  • WS bridge (127.0.0.1:8787) — the trust boundary. Each agent tool call is forwarded as an rpc frame and correlated to its rpc-result by id.
  • HTTP proxy (127.0.0.1:8788) — the script-driven gateway. Point a script's baseURL at a sandbox prefix and the extension rewrites + forwards the request with your cookies injected.

Handshake authentication

The loopback port is public knowledge, so every socket is authenticated in both directions before any business frame flows. The shared token never crosses the wire: 

client → hello   { nonce }                                        (fresh per connection)
server → welcome { proof = HMAC(token, "manta/welcome/" + nonce), nonce }
client → auth    { proof = HMAC(token, "manta/auth/" + nonce) }

Failed or stalled handshakes are dropped; connections carrying a web Origin header are rejected outright; without MANTA_TOKEN the server fails closed.

Single-instance election

Every MCP process races for the bridge port. The winner (owner) hosts the bridge + proxy; losers (peer) forward tool calls to it. When the owner exits, peers re-elect automatically — no manual restart.

Extension UI

Toolbar popup

Clicking the toolbar icon opens a compact menu of every feature:

  • Actions / API Recording / Secure Sandbox — open the side panel on the matching tab. The recording row carries inline start / pause / stop controls; stopping jumps you to the fresh recording in the side panel.
  • Element Capture — starts the in-page inspector (see Element capture).
  • Screenshot — with a persistent Window / Full page toggle.
  • Record GIF — records the current tab, with pause / resume / stop inline.
  • Settings — opens the side panel settings view.

Unsupported pages (chrome://, the Chrome Web Store) are refused; on file:// pages you'll be asked to enable "Allow access to file URLs" first.

Side panel

Tabs for API Recording, Actions, and Secure Sandbox, plus a gear button that reveals the settings view below.

Settings

  • Language — English / 中文, synced live across popup and side panel; defaults to your browser's UI language.
  • Connector — live bridge status (Connected / Connecting / Disconnected / Auth failed — the fix for the last is re-copying the install prompt). The Tools button expands the per-tool kill-switch list: every business MCP tool can be turned off individually.
  • About — extension version + Chrome Web Store link, and the companion npm package with its live registry version.

Recording

Click Start in the popup, use the site normally, click Stop. A MAIN-world script hooks the page's fetch/XHR (no debugger banner) and captures every call — requests and responses — into a local, inspectable call chain stored in IndexedDB. A system notification reports the captured count when the recording is saved.

  • SSE streams (text/event-stream) are captured incrementally via body.tee() — the page keeps its own stream untouched.
  • Manage: rename, delete, and search recordings; while recording, a live pulse + captured-call count follows you across popup and side panel. Individual calls can be deleted from a chain without affecting the rest.
  • Agent description: your agent can write a business-level summary for a recording (set_recording_description); the side panel shows it read-only.
  • Filters: recording filter rules keep the noise out.
  • Not captured: WebSocket frames, sendBeacon, page workers, and native EventSource (fetch-based SSE is covered).

Flow annotations

The call chain is annotated with inferred data dependencies — gold consumes tags mark request fields that reuse a value from an earlier response, blue produces tags mark the response paths that fed them. Inference is deterministic (no LLM): a value of ≥6 characters that appears in an earlier response and is reused in a later request.

Redacted endpoint contracts

The contract view collapses calls by method + normalized path (numeric ids, UUIDs and long hashes become :id) and redacts schema examples to «redacted» whenever a field name looks secret (password, token, authorization, cookie, apikey, csrf, …) or a value looks like a JWT, long hex, base64 blob, or email — so recordings can be shared with your agent safely.

Actions

Recordings are the raw material; Actions are the product. create_action distills a recording into a saved, parameterized, replayable flow:

  • params — named inputs your agent fills at run time (e.g. orderId).
  • steps — the ordered API calls, each re-read from the recording and overridden with templated values.
  • templates — {{param}} for inputs and {{steps[N].outputs[X]}} to feed one step's extracted output into the next request.

execute_action runs the flow end to end through the sandbox gateway — cookies injected, per-host confirmation, full audit.

The side panel Action tab is the browse/manage surface: search actions, inspect declared params and steps (kind, override count, wait ms), delete with confirmation, and the Copy install prompt button. Creation and execution always go through the MCP tools — with user confirmation.

Sandbox gateway

proxy_fetch / proxy_sse take only method/url/headers/body — no credentials. The extension injects your browser cookies at forward time via chrome.cookies + a short-lived declarativeNetRequest rule, so cookie values never reach the AI.

Every forwarded call passes through these gates, in order:

  1. SSRF guard — loopback, private-network, link-local and cloud-metadata addresses (169.254.169.254 included) are refused before any other policy, on every path.
  2. Domain policy — your deny-list blocks outright; your allow-list flows silently. The agent has no tools to read or change either list.
  3. Human-in-the-loop confirmation — every new target host pops an extension-side window showing method/URL/body. Approve once per host per run; deny or ignore and the call never goes out. Covers the agent path and the script path alike.
  4. Inject + forward, then an audit log entry (cookie names logged, values never).

A per-tool kill switch in the extension settings can turn off any MCP tool; proxy-rule enabled is user-controlled too — tools can read it but never change it.

Script-driven gateway

The proxy port isn't only for MCP tools — any HTTP script can use it. Create a rule mapping a local sandbox prefix to a real target, then point your script's baseURL at it: 

# rule: /gh-api  →  https://api.github.com
baseURL = http://127.0.0.1:8788/gh-api

GET http://127.0.0.1:8788/gh-api/repos/marrviin/manta-action-kit
  → forwarded to https://api.github.com/repos/... with your cookies injected

Rewrites are longest-prefix and origin-locked (a crafted path escaping the target origin gets 502; no matching enabled rule gets 404). Responses are sanitized — Set-Cookie is stripped and bodies are capped — and every call passes the same confirmation gate, shown as Script proxy.

The confirmation dialog

  • Shows method (color-tagged), URL and pretty-printed body, plus a source tag distinguishing MCP call vs Script proxy.
  • Auto-denies after a 120-second countdown — deny, close the window, or let it expire and the call never goes out (fail closed).
  • Optional checkbox: add this host to the allowed domains, future requests skip confirmation.
  • While a request awaits confirmation, a system notification appears; clicking it focuses the dialog.

Audit log

Every forwarded call is logged locally with a decision tag (confirmed / auto-allowed / blocked) and status. The sandbox tab offers URL search, export to a log file, and per-row copy actions — URL, response, or a rebuilt cURL (injected cookies appear only as a comment listing their names, never values).

Element capture

Trigger & interaction

Trigger it from the popup's Element Capture row or the Alt+Shift+I hotkey (Esc exits). A DevTools-style overlay follows your cursor: margin / border / padding / content rings, flex & grid gap overlays, and a size badge.

Click an element to capture it with its entire visible subtree; drag to box-select multiple intersecting elements (up to 50, nested by DOM hierarchy).

Captured payload

The capture lands on your clipboard as JSON: tag / id / classes, own text, source location (file / line / column from build-time instrumentation), viewport rect, ~40 computed styles (initial-value and duplicate entries dropped), and the CSS custom properties actually in play. Paste it straight to your agent.

Screenshots

Two modes

  • Window (visible area) via captureVisibleTab; Full page via a one-shot chrome.debugger + CDP captureBeyondViewport — identical to DevTools' "Capture full size screenshot", single render, no scrolling, DOM untouched. The "being debugged" infobar appears only during capture.
  • Pages taller than Chromium's 16384-px capture surface are downscaled to fit (retina sharpness traded for completeness). If DevTools is open on the tab, full-page capture fails with a debugger-conflict hint — close DevTools and retry.

Preview & export

Nothing is auto-saved: the shot opens in a preview tab with click-to-zoom, Copy image and Download — you decide what to keep.

GIF recording

Recording

Record GIF in the popup captures the current tab (offscreen recorder, immune to MV3 service-worker sleep) with pause / resume / stop.

Export

Stopping opens the preview tab with a looping player and two exports: Download GIF (canvas frame sampling, with progress) and Download MP4 (WebCodecs transcode; falls back to the original WebM if conversion fails).

Agent skill

The repo ships a Claude Code skill (@manta-action-kit/skills) that teaches your agent the whole suite — troubleshooting, environment checks, and the recording / action workflows. Install it into any project: 

npx degit marrviin/manta-action-kit/packages/skills/manta-action-kit \
  ~/.claude/skills/manta-action-kit

It includes check-env.mjs, a one-shot authenticated health check for the bridge: 

MANTA_TOKEN=<from the extension> node check-env.mjs

MCP tools reference

Recordings (read + one write)

list_recordingsAll recordings' metadata (id, name, origin, createdAt, callCount).
get_recordingOne recording + its full API call chain (request/response/status/timing).
get_flowCalls as ordered lightweight steps + inferred field dependencies linking them.
get_endpointsDistinct endpoints collapsed by method + normalized path, with REDACTED request/response schemas (+ inputsFrom).
get_callA single API call by id, with full request/response bodies & headers.
set_recording_descriptionWrite a recording's business-level flow summary (the only write path).

Actions

list_actionsAll saved actions (summaries: params, stepCount).
get_actionOne action's full definition (steps, overrides, output extraction paths).
search_actionsFind actions by keyword in name/description.
create_actionDistill a recording into a saved, parameterized action (requires user confirmation).
update_actionPatch an action's content by id (requires user confirmation).
delete_actionDelete an action by id (requires user confirmation).
execute_actionRun an action end to end through the gateway (cookies injected, per-host confirmation).

Proxy rules (script gateway)

list_proxy_rulesList sandbox proxy rules (sandboxPrefix → targetBase, enabled, …).
add_proxy_ruleCreate a rule mapping a local sandbox prefix to a real target base URL.
update_proxy_rulePatch a rule's sandboxPrefix / targetBase by id (cannot toggle enabled).

Authenticated gateway calls

proxy_fetchForward a call through the extension with the user's cookies injected.
proxy_sseLike proxy_fetch, but drains an SSE stream and returns all events.

Every proxy_fetch / proxy_sse / execute_action call passes the extension's own confirmation popup — this covers the script-driven gateway path too and does not depend on the MCP client honoring native permission prompts.

Runtime health

healthReport wsPort, proxyPort, proxyListening, extensionConnected, role.
rebind_proxyMove the HTTP proxy to a free port at runtime (recover from conflicts).

Configuration

  • MANTA_WS_PORT (default 8787) — WS bridge; must match the extension setting.
  • MANTA_PROXY_PORT (default 8788) — local HTTP proxy for the script gateway (must differ from MANTA_WS_PORT).
  • MANTA_TOKEN — handshake secret shared with the extension; take it from the extension's install prompt. Without it the server rejects every client.

Development

pnpm install          # deps + wxt prepare
pnpm dev              # dev Chrome with HMR (auto-loads the extension)
pnpm build            # production build -> packages/extension/.output/chrome-mv3/
pnpm build:mcp        # build the MCP server -> packages/mcp/dist/
pnpm compile          # type-check the whole workspace
pnpm test             # vitest unit suite (security-critical pure modules)

For local MCP development, point your agent config at the built server instead of the published package: 

{
  "mcpServers": {
    "manta-action-kit": {
      "command": "node",
      "args": ["/absolute/path/to/packages/mcp/dist/index.js"],
      "env": { "MANTA_WS_PORT": "8787", "MANTA_PROXY_PORT": "8788", "MANTA_TOKEN": "<from the extension>" }
    }
  }
}
